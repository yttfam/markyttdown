# markyttdown

Tiny native macOS markdown editor. The YTT family's writer.

Open a `.md`, edit, preview, save, save-a-copy. That's the brief.

## Stack

- Swift 6 / SwiftUI, macOS 14+
- Rendering via Apple's [`swift-markdown`](https://github.com/apple/swift-markdown) into `AttributedString`
- Project generated by `xcodegen` (no tracked `.xcodeproj`)
- Sandboxed, hardened runtime, signed + notarized + stapled with Developer ID

## Build locally

```sh
brew install xcodegen
bundle install
xcodegen generate
open markyttdown.xcodeproj
```

Or via fastlane:

```sh
bundle exec fastlane mac test     # build + run unit tests
```

## Release

Releases run on `macos-latest` GitHub Actions. Secrets are mirrored from Vault by:

```sh
./scripts/sync-vault-to-gh-secrets.sh
```

To cut a release, bump marketing version on demand and tag:

```sh
bundle exec fastlane mac bump_marketing component:minor
git commit -am "chore: 0.2.0"
git tag v0.2.0
git push --follow-tags
```

CI's release workflow then:
1. Bumps the build number to `latest GH release build + 1`
2. Builds, signs (Developer ID Application), notarizes, staples the `.app`
3. Wraps it in a `.dmg` (signed, notarized, stapled)
4. Wraps it in a `.pkg` via `productbuild` + `productsign` with Developer ID Installer (notarized, stapled)
5. Attaches both artefacts to a GitHub Release

## Version policy

- `MARKETING_VERSION` — Cali-only, never touched by CI. Bumped via `fastlane mac bump_marketing component:major|minor|patch`.
- `CURRENT_PROJECT_VERSION` (build) — auto-bumped per release commit. Source of truth: highest build number across published GitHub Releases for this repo, +1.

## Layout modes

- Toggle Edit ↔ Preview (⌘1 / ⌘2)
- Side-by-side split

Switch via the toolbar segmented control. Stored in `@AppStorage`.
